# Domain docs

This repo uses a single domain context: the root `GLOSSARY.md` and `docs/adr/`.

Before exploring, read the glossary and any ADRs relevant to the work. If either
is absent, proceed silently. Create domain docs only when a term or decision
has actually been settled.

Use the glossary's vocabulary in issues, proposals, and tests. If a term is
missing, reconsider it or flag the gap for domain modeling. If a proposal
contradicts an ADR, name the ADR and explain why it is worth reopening.
